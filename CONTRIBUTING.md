# Contributing to PhishGuard

Thanks for your interest. This is a hackathon project, but contributions are
welcome under a few simple rules.

## Ground rules

- Keep it small and reviewable: one concern per pull request.
- Run the tests before opening a PR:
  ```bash
  .venv/bin/python -m unittest tests.test_app
  ```
- Do not add secrets, API keys or personal data. `.env` files and key
  material are gitignored; never force-add them.
- The training dataset is generated by `phishguard/build_dataset.py`.
  Prefer editing the generator over hand-editing `data/dataset.csv`, so the
  dataset stays reproducible. If you change the generator, retrain and
  refresh the metrics in the README, report and deck.

## Workflow

1. Fork the repository.
2. Create a feature branch: `git checkout -b feature/your-change`.
3. Commit with a clear message.
4. Push and open a pull request describing the change and the tests run.
5. Keep the AI use disclosure accurate: if you contribute with AI assistance,
   say so in the PR description.

## Code of conduct

All interactions are governed by the project's
[Code of Conduct](CODE_OF_CONDUCT.md).
